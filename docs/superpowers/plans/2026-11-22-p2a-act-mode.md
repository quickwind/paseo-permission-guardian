# P2a `act` Mode with Evidence Gate — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the plugin auto-answer L0 permission requests (allow-once) and optionally L3 (deny-once) only after a replay-based evidence gate passes, after first closing classification gaps that would become wrong auto-allows.

**Architecture:** Hardening lands first (Tasks 1–3) so no later task can make a gap live. The audit store gains the data the gate needs (Task 5); a pure replay function and a pure gate state machine (Tasks 6–8) compute the effective mode; a responder (Tasks 9–10) answers through `context.paseo` only when the gate says `act`. UI and docs close it out (Tasks 11–13).

**Tech Stack:** TypeScript, Node 22, Zod, Vitest, `@getpaseo/plugin` 0.16, React Native primitives on the client.

**Spec:** `docs/superpowers/specs/2026-11-22-p2a-act-mode-design.md` (v3, approved) and `docs/adr/0008-act-mode-evidence-gate.md` (Accepted). Section references (§) below point to the spec.

## Global Constraints

- Fail to human: any error, unknown payload, ambiguous option, parser failure ⇒ no answer (never auto-allow, never auto-deny on error).
- L2/L3 are never lowered; L1 is always `ask` in P2a.
- No cross-state caching for deterministic decisions; replay results feed only gate metrics.
- Pure Node.js, no native addons; runtime boundaries: `client/` never imports `server/` or `node:*`; `shared/` holds only Zod schemas, `defineSettings`, `defineRpc`, DTOs.
- Never select persistent options (`/always|session|remember|forever|all|persist/i`); never send `updatedInput`/`updatedPermissions`; never respond without `selectedActionId`.
- Gate defaults: `minSamples` 200 (min 20, max 5000), `windowDays` 30 (1–365), `autoFallbackOnFalseAllow` true, `allowOverride` true; replay bound 20 000 records; attribution window 15 000 ms; unconfirmed pause after 3 consecutive; `modifiedFiles` snapshot cap 200; deny message ≤500 chars.
- Auto-answering enabled for provider `agy` only.
- Before reporting any task done: `npm run typecheck`, `npm run check:boundaries`, `npm test` pass.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Agent replies or is interrupted while the plugin is mid-decision** (after-event arrives first, or a cancellation arrives as `deny` without `selectedActionId`) — expected: no answer sent, the deny counts as a human denial (annotatable), gate falls back. Tests in Task 10.
2. **Audit history from before P2a** (no `offeredActions`, no `contextSnapshot`, `includeRawInAudit` off) — expected: replay never gains samples from it, but its human denials still count. Tests in Task 7.
3. **Daemon restart while latched** — expected: `gate-state.json` is re-read, replay runs, effective mode is `shadow` until replay finishes, then `act` if the latch is still valid. Test in Task 8.
4. **User edits gate parameters while in `act`** (raises `minSamples`, disables override, turns off auto-fallback) — expected: effective mode recomputed immediately per §3.2. Tests in Task 8.
5. **Large or malformed audit directories** (rotated `.1.jsonl` files, a truncated last line from a crash) — expected: rotated files are read; a truncated final line in the currently-open file is not "corrupt" (it is tolerated if it is the last line of the newest file), any other unparsable line ⇒ `unavailable`. Tests in Task 5 and 7.
